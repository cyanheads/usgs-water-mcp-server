# 0.7.0 — 2026-11-23

## Added

- **`water_get_series` and `water_get_site_data_catalog` read field measurements and annual peaks** ([#56](https://github.com/cyanheads/usgs-water-mcp-server/issues/56)). `seriesType` takes `field` (hand-measured values such as a well's groundwater level) and `peak`; their records carry the date's known part, observing procedure, rating, water year, and qualifiers. The catalog lists them under `readingType`, one list across both metadata collections; a failed field-series read ends a catalog page at the time series, with the cursor at the field series. `statCd` on a field or peak series fails with `stat_cd_for_field_or_peak`.
- **`water_find_sites` `lastObservedAt`** counts a field measurement's or peak's recorded time of day ([#56](https://github.com/cyanheads/usgs-water-mcp-server/issues/56)).
- **`water_list_parameters` `limit`, `offset`, and `nextOffset`** page a query's matches or the curated list; the catalog figure is ~19,700 codes ([#60](https://github.com/cyanheads/usgs-water-mcp-server/issues/60)).
- **`water_get_readings` accepts up to 500 `sites`**, reads the first 100 distinct, and returns the rest as `deferredSites` to resubmit ([#61](https://github.com/cyanheads/usgs-water-mcp-server/issues/61)).
- **`water_get_conditions` ranks up to 100 sites per call** through `sites` (`site` is still accepted as an alias), with `missingSites` and `deferredSites` as in `water_get_readings`; Statistics reads are batched across sites, and a site whose statistics fail returns its reading with `historicalContextStatus: "unavailable"` ([#62](https://github.com/cyanheads/usgs-water-mcp-server/issues/62)).
- **Instantaneous, field, and peak staged tables gain `time_utc`**, a UTC instant that orders as text; use `CAST(time_utc AS TIMESTAMPTZ)` for windows relative to now ([#59](https://github.com/cyanheads/usgs-water-mcp-server/issues/59)).

## Changed

- **Breaking: `water_get_conditions` returns `conditions[]`**; the 13 per-site fields 0.6.0 returned at the top level move unchanged into `conditions[i]` ([#62](https://github.com/cyanheads/usgs-water-mcp-server/issues/62)).
- **Breaking: `water_get_series` `statCd` and `otherSeries[].statCd` are nullable** (null on field and peak series), and **`water_get_site_data_catalog` `seriesType`** gains `field` and `peak`; a `Max At Event Time` row 0.6.0 reported as `null` reads `peak` ([#56](https://github.com/cyanheads/usgs-water-mcp-server/issues/56)).
- **Breaking: staged series `value` is DOUBLE** with declared table schemas, so SQL that treats it as text (`LIKE`, `substr`, `length`, `COALESCE(value, 'n/a')`, `CASE … ELSE value`) fails, and `CAST(value AS VARCHAR)` reads `900.0` where it read `900`. A `water_find_sites` basic-mode table's numeric columns are DOUBLE too ([#59](https://github.com/cyanheads/usgs-water-mcp-server/issues/59)).
- **Breaking: a `water_get_site_data_catalog` cursor issued by 0.6.0 returns `invalid_cursor`** (cursors are version 2) ([#56](https://github.com/cyanheads/usgs-water-mcp-server/issues/56)).
- **A spilled series' inline preview is sized by the staged rows' width**: a spilled instantaneous series returns about 15% fewer records inline (measured 476 → 406), a daily one slightly more. Every record is still staged and the notice states the inline count ([#59](https://github.com/cyanheads/usgs-water-mcp-server/issues/59)).
- **`water_find_sites` `limit` defaults to 25** (maximum 500); pass `limit: 500` for the former page ([#57](https://github.com/cyanheads/usgs-water-mcp-server/issues/57)).
- **`water_dataframe_query` renders every returned row in `content[]`**, cells encoded and NULL as `*null*`. Rows cap at 5,000, or the deployment's `CANVAS_DEFAULT_ROW_LIMIT` when lower ([#58](https://github.com/cyanheads/usgs-water-mcp-server/issues/58)).
- **README, `docs/design.md`, the `usgs-water-guide` skill, and server `instructions`** describe field and peak series, multi-site calls, and typed staging.

## Fixed

- **`water_list_parameters`** escapes catalog text and the query in `content[]`; 0.6.0 wrote them raw.
- **A call cancelled before it waited on the shared parameter-catalog or statistic-name read** no longer leaves that read's failure unhandled.
