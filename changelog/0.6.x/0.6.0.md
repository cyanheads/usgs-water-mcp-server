# 0.6.0 — 2026-11-11

## Added

- **`USGS_API_KEY`** is an optional api.data.gov key sent as `X-Api-Key`, also exposed as plugin and `.mcpb` user config ([#32](https://github.com/cyanheads/usgs-water-mcp-server/issues/32)). Without one the Water Data APIs allow 1,000 requests per hour per IP on the OGC collections and 4,000 on the Statistics API; a shared or hosted deployment should set one.
- **`water_find_sites` `lastObservedAt` and `observedWithin`** ([#52](https://github.com/cyanheads/usgs-water-mcp-server/issues/52)). Each row, inline and staged, carries the UTC time of the newest observation among the series matching `parameterCd` and `hasDataTypeCd`; null means no matching series, or none with a recorded time (shown as "none recorded" in `content[]`). An ISO 8601 `observedWithin` keeps only sites whose `lastObservedAt` falls inside it.
- **`water_get_conditions` ranks depth-to-water as a water level** ([#53](https://github.com/cyanheads/usgs-water-mcp-server/issues/53)). For 72019, 30210, 99019, and 72276 a shallower depth ranks higher and `p05` is the deepest; `percentileLabel` and `comparisonBasis` say so, and `currentValue` stays the raw depth.

## Changed

- **Breaking: `water_get_series` `methodId`** takes the 32-hex OGC `time_series_id` the series response returns. A stored numeric WaterServices method ID (e.g. "68478") fails with `method_not_found`.
- **Breaking: `water_get_readings` `period`** takes at most 1,100 days, the longest window the `continuous` collection serves. A longer period (e.g. `"P4Y"`) fails with `invalid_request`.
- **Breaking: `water_find_sites` `hasDataTypeCd`** accepts only `iv` (aliases `uv`, `rt`), `dv`, `gw`, and `pk`. `qw`, `sv`, `ad`, `aw`, `id`, and `all` fail with `invalid_request`.
- **Breaking: `water_dataframe_query`** refuses a DuckDB metadata-view name (such as `duckdb_tables`) used as a column alias or CTE name with `system_catalog_access` (mcp-ts-core 0.13.22's SQL gate).
- **Every tool reads the USGS Water Data APIs** (OGC collections and the Statistics API) instead of WaterServices, which shuts down 2027-02-22 ([#32](https://github.com/cyanheads/usgs-water-mcp-server/issues/32)). Tool names and schemas are unchanged apart from the items here. Errors come from the APIs' JSON bodies: a 429 is `RateLimited` carrying `retryAfter` (on the statistics side of `water_get_conditions`, the reading still returns, with `historicalContextStatus: "unavailable"`), and a rejected key names `USGS_API_KEY`.
- **Values that differ from 0.5.0 for the same call:** `hucCd` is 12 digits for most sites (was 8); coordinates carry full precision; `methodId` and `statSeriesId` are 32-hex OGC ids; `parameterName` is the parameter catalog's description; method labels and qualifier words follow the Water Data APIs, and a value below a reporting limit is null with the upstream qualifier words; zero-value sibling series are returned; sites with no time zone report `+00:00`; percentile thresholds are no longer rounded to 3 significant figures.
- **Selection and lookup differences:** `historicalContextStatus` separates `no_matching_day` from `no_record`. At a base/auxiliary gage pair with tied record counts the default series is the base gage (`methodDescription` null); where every candidate sensor is labeled and tied, it is the series that began first. HUC `02070008` returns one more site than WaterServices (VA087-390347077203001). An unknown `siteType` gives `no_sites_found` (was the upstream 400). A `parameterCd` filter no longer matches sites whose only record of the parameter is water-quality samples. A site number held by two agencies is listed once per agency.
- **Upstream requests per call** (0.5.0 sent one WaterServices request per call, two for `water_get_conditions`): `water_find_sites` 2–5; `water_get_readings` 4 cold, 2 warm; `water_get_series` daily 2 warm and up to 5 cold, instantaneous 1 for metadata plus 1 per page per site-local 366-day window, and 2 more cold; `water_get_conditions` 7 cold and 5 warm, one fewer when the site has no daily-mean series for the parameter; `water_get_site_data_catalog` 1–2; `water_list_parameters` 0–1; the site resource 1–2.
- **`stateCd` resolves `FM`, `MH`, and `PW`** (FIPS 64, 68, 70). **`water_get_series` `statCd`** accepts `"00011"` on an instantaneous series, the statistic `water_get_site_data_catalog` lists there, and reads it as `"00000"` (0.5.0 rejected it).
- **`water_find_sites` `parameterCd` and `hasDataTypeCd`** descriptions say "has ever reported" and point to `lastObservedAt` and `observedWithin`.
- **`usgs-water-guide` skill, README, `docs/design.md`, and server `instructions`** describe the Water Data APIs, `lastObservedAt`, and the depth ranking.
- **Development skills and scripts** are resynced with mcp-ts-core 0.13.22, including the JWT audience and issuer variables in `.env.example`.

## Fixed

- **`no_data_for_parameter` recovery** on `water_get_readings` and `water_get_conditions` points at `water_get_site_data_catalog`; `water_get_series` `no_data_for_range` points at the catalog's `beginDate` and `endDate` ([#52](https://github.com/cyanheads/usgs-water-mcp-server/issues/52)).
- **`water_get_readings`** returns the zero-value series for an all-dormant batch, as a mixed batch already did, and raises `no_data_for_parameter` only when no requested site returns a series ([#52](https://github.com/cyanheads/usgs-water-mcp-server/issues/52)).
- **`water_dataframe_query`** passes the framework's own recovery hint through for a `PIVOT` without `IN` and for SQL syntax errors, and `system_catalog_access` names the matched catalog.
- **`water_dataframe_describe`** honors cancellation.
